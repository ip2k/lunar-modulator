# Effects expansion research: Eurorack and open guitar pedals

**Date:** 2026-10-09
**Status:** research and prioritization only; no DSP code was copied or implemented.
**Target:** future browser/desktop scenes and, only after profiling and the existing device-safety gates, a possible FM-1 build.

## Finding

Lunar already has a substantial effect set: Plate, Ensemble, Diffuse, PSX Verb, Crush, Fold, Drive, Echo, Filter, Comb, Comp, Limiter, DJ Filter, Tilt, Master Sat, Isolator, EQ, Room, Hall, Gate, Squash and Transient ([current engine inventory](../engines/README.md)). Another generic filter, drive or reverb would add little. The best next additions are a small, tempo-controllable **Warble** (wow/flutter) and a performance-oriented **Repeat** (stutter/hold/tape-stop) that reuse the existing Echo buffer where possible. A classic phaser is a distinct, medium-priority gap. Pitch shifting is already a reviewed, concrete candidate in the Clouds survey; it should be evaluated alongside these rather than duplicated by a new guitar-pedal port.

This ranking is not a claim that any candidate runs on the FM-1. The documented 240 MHz, 578 KB SRAM and ~44.1 kHz figures are reported platform facts; none of the new candidates has a measured pi32v2 cycle or device-memory result. Daisy Seed, Cortex-M4 and desktop measurements do not transfer directly.

## Scene palette for the four demo styles

These are effect-chain directions for later composition, not completed or tested presets. Each row suggests one distinct palette that can evolve through four scenes without requiring a new effect in every scene.

| Style | Four-scene arc | Distinctive additions needed |
| --- | --- | --- |
| **Chillwave** | 1) soft filter + light Ensemble; 2) introduce Warble and longer Echo; 3) open Room/Plate send and deepen modulation; 4) pull the filter back and let the delay/reverb tail carry the transition. | Warble first; tempo/reset-capable Echo controls. Existing chorus/reverb cover the rest. |
| **Future bass** | 1) filtered, close sound; 2) add octave/pitch movement and sidechain-style duck; 3) bright Drive/Filter lift with synchronized echoes; 4) remove low end, hold/release a Repeat gesture into the next section. | Pitch (already surveyed), tempo-locked Echo/Repeat, and a usable duck/key path; most needed building blocks are already present or in the options note. |
| **Vapor twitch** | 1) Crush and narrow Isolator; 2) Warble plus short Echo; 3) stutter/hold/reverse gestures over a spectral/granular layer if later justified; 4) stop/release into a filtered tail. | Repeat first, then optional spectral processing only after profiling. Avoid making FFT/granular a prerequisite for the style. |
| **Electropop** | 1) tight Filter/Comp; 2) rhythmic Phaser sweep; 3) widen with Ensemble and sync delay; 4) return to dry/filter focus for a clean next-scene downbeat. | A compact Phaser and tempo-capable Echo; the rest exists. |

The existing scene/chain model should be exercised with these palettes before adding new DSP: use currently available effects to prove that four linked scenes can create a clear build/variation/release arc. Then make Warble and Repeat candidates earn their cost with reference renders and exact bypass/transition tests. Keep phrase/scene authoring work separate from this research note.

## Implementation sequence and gates

1. **Composition proof:** construct four-scene mock chains from the current effect registry for each palette above; record where current effects fail to produce the intended sound. This is a browser/desktop task and must not be described as device validation.
2. **Warble:** if the gaps justify it, write a small self-contained effect. Test deterministic per-instance modulation, finite parameter handling, correct sample-rate scaling, exact dry/bypass and mix-zero behavior, and mono/stereo state. Measure native and Wasm CPU and memory. Do not import CHOMPI’s full tree.
3. **Repeat:** specify hold/capture/retrigger/clear behavior and edge smoothing; use Echo’s existing storage if possible. Define clock division and tempo-jump policy against the engine transport API before implementing tempo sync. Test timing across transport reset, tempo changes and four chained scenes.
4. **Phaser and Pitch:** phase it behind measured CPU/SRAM budget. Reuse the existing Clouds pitch-shifter evaluation rather than a Daisy port. For any new third-party code, pin commit, preserve copyright/license, inspect included headers and dependencies, and place it in `third_party/<name>/` with `UPSTREAM.md`.
5. **Spectral/granular:** only after profiling current multi-scene workloads. Prototype at a reduced rate/overlap on desktop/Wasm first; estimate actual persistent and stack buffers; measure target-core cost later on an authorized dev kit. Do not use or transfer pedal firmware/models/IRs as a shortcut.
6. **Device gate:** no device traffic or flash/write test is part of this work. Any eventual device investigation must follow the current staged hardware policy in `AGENTS.md` and the experiment-specific authorization and recovery plan; this research does not authorize device activity.

## Tooling and evidence limits

Rarefaction reported the original checkout as its project root rather than this isolated worktree and did not start clangd. Serena activated this worktree path but could not resolve the requested effect-registry file. Semantic navigation was therefore unavailable for this research pass; this note relies on the existing audited project notes, the current `engines/README.md` inventory, and the linked upstream pages. No hardware, device traffic, DSP build or CPU benchmark was run. Every new RAM/CPU estimate above is marked as a prior estimate or left explicitly unmeasured.
