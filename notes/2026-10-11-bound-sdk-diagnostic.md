# Bounded private SDK diagnostic policy

2026-10-11; personal, non-commercial. Source milestone only. The intended goal remains a working diagnostic image on the owner's FM-1; this policy supplies a bounded, device-free transaction boundary and does not establish physical installation or recovery.

[verified: source] `tools/fm1_bound_sdk_diagnostic.py` adds a separate scope for one private SDK application and the reviewed fixed-loader backup profile. It leaves the original SDK-free policy and original-loader gate unchanged. `prepare_transaction` seals sector `0x4000` last for both install and restore; `load_policy` requires `baseline_profile='fixed-loader'` and an explicit direction. No SG opener, ROM entry/upload/jump, physical CLI or hardware operation is provided.

[verified: source] The factory requires the actual app and ELF, two matching transaction backups, target, manifest, identity, raw references, campaign, historical entry log, backup command log, and independently relocated actual fixed-loader/profile files. Historical campaign path names are metadata and are not opened. The actual app/ELF are pinned to `991b569df7d131320e42ef34c1b619de586d2a7ba6236c0ea1c089731eb61fa9` and `8832aa4677a7da3aa7871da58a092e5c3e69d766b31d5e67744301ce437979e2`; actual native/key and raw layout gates are recomputed. [verified: source] Evidence bytes, including three fixed-backup implementation sources and six reference files, are captured during validation and rechecked at bind, run entry and before every mutation. Final-component symlinks, non-regular files and oversized evidence are rejected; the command log limit is 16 MiB. Factory outputs have identity-based authorization, so ordinary `dataclasses.replace` copies cannot reuse validation. Python remains trusted caller code rather than a security sandbox; private ancestor directories and the execution snapshot are operator responsibilities.

[verified: source] An injected transport must claim the exact fixed-loader session, identity and backup provenance. Inherited framing checks capture the entire binding before and after each exchange and latch/close ambiguous failures without retry. Program pages are direction-bound and require an exact durable intent; erase/program addresses are limited to the raw gate's derived changed sectors. The transaction rereads the full NOR, rejects protected changes, verifies erase/program readback, and resumes from actual contents rather than trusting journal progress. Completed journals still require fresh NOR verification.

[inferred from ordering] Writing the directory sector last avoids publishing the new app directory before its other changed sectors have been verified. It does not make a multi-sector install atomic or prove that an interrupted image boots. A fresh recovery session and full NOR revalidation remain necessary after ambiguity.

[verified: source] Backup evidence checks its prepared/completed log envelope and the exact request-inventory hash. It does not independently replay all 8757 requests, attest process exit, prove current live entry, or establish kernel exclusivity. Receipts explicitly retain `protocol_mock_only=true`, `hardware_validated=false`, `physical_loader_recovery_binding_proven=false`, `historical_entry_only=true`, and `backup_log_replay_verified=false`.
