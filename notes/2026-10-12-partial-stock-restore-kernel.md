# Distinct partial-NOR stock restoration kernel

This is a new closed kernel, not production recovery authority. The old full-target restore guards remain unchanged. `prepare_campaign` rejects before evidence IO and also rejects if a caller supplies an acquisition pin: genuine acquisition composition has not been implemented. There is no SG opener, CLI, upload, reset or eFuse command.

The pure byte constraints require matching complete 1 MiB partial preimages and the exact owner stock SHA `96006a51917750743d7adc68461f1289e82adc004a75bd2bbd5da40ecc44c4e4`. Dirty sectors must be a subset of an original authenticated mutation whitelist. SPL before 0x4000 and OTA/cfg/tail from 0xACF40 must match stock directly; other unauthorized sectors must match stock. A torn directory is never parsed to establish authority. A new transaction represents actual partial preimage to genuine stock desired image, purpose `stock_restore`, internal transaction action `install`, with directory sector 0x4000 last when dirty. Existing journals cannot grant a new run.

The injected worker reuses exact pinned transaction source `d0527efb...`, with its geometry import supplied privately after checking the exact original header source `28317ee5...`. It freezes inputs before the generic transaction loader's ordinary readers. Exact-instance registration rejects copied policies. Durable exclusive receipt and consumption precede transport creation. Every request checks positive/negative evidence and binding before and after its durable intent. Only fixed FC0A, bounded FD05, authorized FB01 and exact-stock FB04 are permitted. Mutation exceptions latch, close and consume; operation return does not erase uncertainty. Only actual matching page readback subtracts attempted page spans. Full final stock readback and no uncertainty are required for completion. Close errors remain sticky.

Focused tests use explicitly synthetic images, stock pin override and injected transport registration. These tests do not authenticate a physical acquisition, characterize SG_IO statuses or prove ROM availability, NOR behavior, boot or recovery. Future physical admission requires reviewed fixed-loader provenance, whole matching dual dump command/page replay, owned capture and current exact binding, original consumed-campaign whitelist, preserved authentic stock/protected bytes, immutable sources and absent ambiguity artifacts. A future native adapter must validate real SG completion fields and preserve ambiguity. Python private registries do not defend against arbitrary trusted Python code.
