# Browser OTA adapter review

**Scope:** read-only design review for a future Lunar browser installer. No source, device, or deployment changes were made. Confidence labels below describe what was checked in this review.

## Source and fit

[verified] Felucca's local reference is `reference/Felucca` at `b0dcd53a251d5f5392fea9478b48244d322eeb2a` (2026-10-06); its `web/fm1ota.js` is GPL-3.0-only. The current upstream `main` was `1727537624390cc3f9c7dff2456b43b3a8edb005` at review time, so the pinned local copy is behind. Compared the upstream and local browser sources; this review's line pointers below refer to the local pinned copy. Sources: [upstream browser updater](https://github.com/hugelton/Felucca/blob/main/web/fm1ota.js), [upstream fake-MIDI tests](https://github.com/hugelton/Felucca/blob/main/web/test_web.mjs), [upstream CLI reference](https://github.com/hugelton/Felucca/blob/main/tools/fm1_install.py), [Web MIDI specification](https://www.w3.org/TR/webmidi/).

Felucca is a useful working protocol reference, but its GPL implementation cannot be copied into Lunar's MIT core without an explicit licensing/build-boundary decision. The smallest safe first implementation is an independently maintained, transport-neutral Lunar protocol module, with a thin Web MIDI adapter and no change to the existing simulator MIDI-input surface (`sim/web/www/app.js:970`). Web MIDI requires a secure context; SysEx access uses `requestMIDIAccess({sysex: true})` and can be denied by browser/user policy. Request access only after a clear user action and explain that this operation updates firmware.

## Findings

| Priority | Finding | Evidence and consequence |
| --- | --- | --- |
| P1 | Success can be reported after a failed finish response. | `Updater.serve` sends the `success` response at `fm1ota.js:158-160` but ignores `Link.send()`'s boolean result; `install` then advances on `finished`. `install` and `write` also ignore `send(UPGRADE)` at lines 181 and 204. A disconnect/error may therefore look like completed verification/write. Treat every failed send as a transfer failure; a finish exchange is complete only after the ACK send succeeds. |
| P1 | Resume is not tied to an immutable artifact. | `resume(image, ..., product)` at `fm1ota.js:211-228` filters an optional model, but has no image digest or persisted attempt binding. A different same-model image can be supplied on retry. Hash the validated artifact once, pin it through the attempt/resume state, and reject mismatches. The loader does not attest to the image hash, so this is a client-side continuity guarantee only. |
| P1 | Port selection is heuristic and can roam after re-enumeration. | `find` at lines 117-131 probes matching port names and pairs the first output with exactly the same name; IDs are not pinned and `waitFor` repeatedly rescans all ports (`134-142`). Require explicit user-selected input/output IDs for the initial device and an unambiguous, user-confirmed re-selection after loader reboot; never probe unrelated equipment or silently select a different matching unit. |
| P1 | Preflight identity is weaker than the post-install check. | `install` derives the target model from `product` and checks only model before sending upgrade (`174-180`); exact `product` equality is only checked after reboot (`194-198`). Parse/validate the package identity and expected model/version before opening ports, show both to the user, and preserve exact post-reboot identity verification as the only installed-result claim. |
| P2 | Request/identity parsing omits declared-length and checksum checks. | `parseRequest` (`50-58`) checks outer framing, decoded length, header and checksum but not declared body length `u[3:6] == 8`. `parseIdentity` (`60-66`) checks decoded size/header but not outer F0/F7, declared length 27, or checksum. Lunar's capture-driven `reference/FM-1-RE/tools/fm1_ota.py:97-128` does validate these fields and is a stricter independent oracle. Match those checks in the new parser. |
| P2 | Queue and overall operation lifetime are unbounded/extendable. | `Link` appends every F0 frame to an unbounded array (`68-94`); `serve` refreshes idle time on every valid request (`146-170`), so sustained traffic can keep the operation alive indefinitely. Use a bounded single-consumer queue with overflow failure, and monotonic per-stage hard deadlines plus idle deadlines that cannot be extended beyond the hard cap. Close/unsubscribe the link on every exit. |
| P2 | Zero-length data reads at image end are accepted. | Range check `addr + len > image.length` (`163`) permits `(addr == image.length, len == 0)` and does not explicitly reject a zero-length data request. Lunar's Python reference rejects `addr > len(image)` but also permits the exact-end empty slice (`fm1_ota.py:296-300`). Decide and test the policy explicitly; safest is to reject zero-length data reads and permit only valid in-image ranges, keeping the finish addresses as separate control cases. |
| P2 | Existing fake-MIDI coverage is too permissive for a stricter parser. | `reference/Felucca/web/test_web.mjs:1197-1277` covers success, unplug, and no-device. Its fake request encoder sets the declared body length bytes to zero (`1250`), so it must be corrected to encode 8 before adding strict length validation. Add negative/fault injection coverage described below. |

The local Felucca Python implementation (`reference/Felucca/tools/fm1_install.py`) has the same important send-result and parser gaps; it is not an independent reason to reproduce those behaviors. Lunar's capture-driven Python transport already checks request and identity lengths/checksums and bounds `addr > image length`, while explicitly handling a failed control response (`reference/FM-1-RE/tools/fm1_ota.py:97-128, 287-310`).

## Bounded implementation path

1. Add a transport-neutral protocol core that accepts already validated immutable package bytes and returns explicit request/identity results. Independently implement strict SysEx framing, pack/unpack, checksums, length fields, address/length checks, and the fixed 512-byte request maximum. Do not copy Felucca source into the MIT tree.
2. Add a Web MIDI adapter that opens only the user's selected pair, requests SysEx permission from an explicit action, enforces bounded queue/deadlines, checks every send result, and fails closed on disconnect or ambiguous re-enumeration. Bind retry state to the package SHA-256 and target identity.
3. Before transfer, validate and display package model/version and the device's parsed identity. Keep stage 1 verification and stage 2 write as distinct progress states. Report success only after a successful finish ACK and a rebooted device reports the exact expected model and version.
4. Add fake-port tests with deterministic timers: complete handshake/verify/write/reboot; valid declared lengths; bad outer framing/header/length/checksum/identity; 0, 512, and 513-byte reads plus end-of-image and out-of-range addresses; `send()` throwing at upgrade/data/finish; queue overflow; idle and hard deadlines; disconnect and ambiguous port re-enumeration; wrong-model package/device; resume with changed artifact hash; and exact post-reboot identity mismatch. Correct the fake's body length before using it as an oracle.

Keep this first increment offline-testable and limited to building/validating protocol and UI consent flow. No browser installation, hardware admission, user default, or successful playback has been established by this review.
