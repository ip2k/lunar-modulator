# Browser package admission boundary

Status: offline audit and fail-closed browser gate; no device connection, write, release package, or install admission.

## Artifact formats and current blockers

The browser OTA protocol consumes the logical flash image served for address/length requests. A bare `app.bin` from `tools/native/build_application_probe.py` or `tools/native/build_demo_image.py` is only a linked application payload; it is not a complete flash image or a JieLi UFW/FWSC package and must be rejected before a transport session can be created. An expanded-d9000 candidate is a 1 MiB raw-flash geometry artifact (`tools/jieli/expanded_flash_profile.py`), not an OTA container, and its current receipt explicitly leaves provenance, ELF, OTA packaging, settings migration, hardware admission, and installability false.

The only current stock-derived OTA-shaped output is `tools/native/ota_candidate.py::compose`, a private V15/native-controls prototype pinned to one stock package and app. Its receipt says `release_ready: false`, `web_install_verified: false`, `physical_boot_verified: false`, and `recovery_verified: false`; its app is a 20-second probe, not the all-engine demo image. It is not an acceptable general or demo installer artifact.

`tools/jieli/inspect_fwsc.py::inspect` checks the interleaved identity markers, UFW header and entry-list CRCs, established entry bounds, payload CRCs, and FWSC trailer marker. It deliberately returns `packaging_ready: false` and leaves nested flash/JLFS/SFC CRC and repack validation, guarded-component correspondence, remaining UFW metadata/trailer semantics, and device version acceptance pending. `tools/jieli/inspect_stock_flash.py::inspect_nested` validates a stock V15 nested image and a full no-op reconstruction, but still returns `packaging_ready: false`; modified image repacking and candidate/runtime gates remain open. These readers are inspection evidence, not a browser admission authority.

Before a future artifact can be admitted, its exact supported model/version and target must be pinned; package bytes must be bound to a complete independently checked logical image; nested JLFS/SFC/directory checks and exact component hashes must pass; and policy checks must prove stock SPL SHA-256 `730e54f0a439f58d147be4364ad21e19566945ada9d3a7bbc8371dce5068d3ef` (14,384 bytes), byte-identical `top/isd_config.ini`, `ota.bin`, and `files/cfg`, and no foreign SPL/loader (`tools/jieli/package_guard.py::check_package`). Expanded-d9000 additionally needs independently validated relocation, settings migration/export and rollback. The exact app/image still requires the project’s explicit startup, recovery, fresh backup, and physical acceptance gates. No caller-supplied `installable: true` or parsed magic string can substitute for these checks.

## Decision

Implement the browser-side boundary as a bounded format classifier and fail-closed verifier: reject empty, bare app, raw flash, malformed container, and all currently recognized FWSC candidates as non-admissible. The verifier must never return the `logicalImage` capability consumed by `native-ota-adapter.js`. A future release-grade verifier can replace this only after Python/native guards expose a complete, versioned, reproducible receipt whose hashes are recomputed in-browser or authenticated through a separately reviewed trust path. No UI, MIDI permission, port selection, transport, or write is wired here.

## Validation limits

Use generated/synthetic bytes for malformed and bare-artifact tests. The private Python FWSC composer requires an ignored stock V15 package and private native app, so those vendor-derived inputs are not committed. When available, its output can be passed to the browser classifier as a cross-check and must remain blocked until all release gates change. No vendor binaries or package fixtures belong in this repository.

Implementation checkpoint: `sim/web/www/native-package-admission.js` is inspection-only. It recognizes the FWSC interleaved identity marker shape, ELF, exact 1 MiB raw images, empty input and unknown input, but always returns `admissible: false`; its `verifyNativePackage()` always rejects, so it never supplies `logicalImage` to the OTA adapter. `sim/web/test/native-package-admission.test.mjs` covers each class and malformed identity markers. The optional `LUNAR_PRIVATE_FWSC_FIXTURE` cross-check was run against `build/native-controls-16-20261012/private-ota-candidate/lunar-native-controls.fwsc`, emitted by the existing Python `tools/native/ota_candidate.py` composer; it was correctly recognized as a candidate and remained blocked. A real private all13 `app.bin` (`build/mixed-project-all13-no-writeback-v4/linked/artifact/app.bin`, 845,432 bytes) was independently passed through the classifier and returned `unknown`/not admissible. No private or vendor binary was added to git. These checks establish fail-closed classification only, not full FWSC parse, release admission, or device behavior.
