# Compressed wavetable profile at the private build-worker boundary

Status: source review only, 2026-10-14. Reviewed exact Hera branch base `4887528d1b2841431dceb95fbe9a835c36c790f9` on `codex/2026-10-14-compressed-worker-review`. No source, builder, API, catalogue, device, or admission changes were made. This note distinguishes current implementation from a selectable profile design; no image is installable or storage-admitted.

## Current end-to-end path

`BuildRequest` in `tools/installer_service/api.py:39-60` permits strict engine/effect/MIDI/modulation IDs, ordered project IDs, and startup index; unknown fields are rejected. `read_bounded_json` (`api.py:230+`) validates each module against the trusted kind catalogue and each project against the trusted project set. The request is canonicalized and hashed before `docker_adapter` submits it. `tools/installer_service/docker_worker.py:87-100` has a fixed invocation of `tools/native/build_demo_image.py`; browser input cannot choose source paths, toolchain, catalogue, or CLI flags.

`build_demo_image.py:107-140` prepares a request-bound project profile and currently hardcodes `--indexed-tft`, `--compressed-wavetables`, and `--flash-plaits-wavetables`, together with 12 Shapes voices, the expanded link layout, SAVE service, and startup index. There is no request-level table policy. The builder then reopens the prepared profile against its SHA and checks selected modules/project assets at `checked_link_receipt` before emitting its diagnostic-only image receipt.

`build_application_probe.py:303-313` derives table namespaces from the resolved module selection, removes corresponding cached resource objects from the checked catalogue, then regenerates those resource translation units from pinned source assets. It pins `tinf`, records each table's source-derived raw and packed bytes/hashes (`prepare_wavetables.py:12-60`), and links table decoder and inflater. Its checked 16-shard catalogue requires all-modules/GPL, `-Oz`, LTO, 12 Shapes voices, indexed TFT mode, matching current `source_manifest`, identical object lists, and per-object hashes (`build_application_probe.py:133-173`). That source freshness check is an important guard against accepting stale prebuilt module objects.

At runtime `firmware/native/app_probe.c:177-187` calls `lunar_wave_tables_init()` before `fm1_app_init`, save-service readiness, instance-pool setup, or project startup. `firmware/native/wave_tables.c:17-47` bounds each decode, checks output length, delta-decodes and verifies the raw FNV hash. On any table failure, startup stops audio, detaches USB, clears the boot guard and enters UBOOT. This is a useful fail-closed order; there is no render-time decompression.

## Memory accounting and current-profile correction

The linker receipt's `instance_pool_bytes` is a residual instance-pool budget, not a total-RAM figure. The formula at `build_application_probe.py:381-385` starts with 192,000 bytes, adds the indexed-TFT app-struct credit, then subtracts the raw decoded wavetable sizes. The reviewed all-13 receipts show indexed-TFT credit 57,088 bytes. Asset sizes pinned in `evaluate_wavetables.py` are Plaits 50,688 bytes and Braids 33,024 bytes.

Current worker options retain Plaits in XIP (`--flash-plaits-wavetables`) and decode Braids for Shapes, so the current all-13 profile's reported residual pool is `192000 + 57088 - 33024 = 216064` bytes. This is confirmed by the retained `notes/2026-10-14-all13-fullsong-link-comparison/chunk-codec-followup/target-verification.json` receipt (`flash_plaits_wavetables: true`, one table record, `instance_pool_bytes: 216064`). The 165,376-byte number is the different both-decoded profile: `192000 + 57088 - 50688 - 33024 = 165376`. Do not describe 165,376 as the current worker's pool unless its selected profile decodes both banks and its receipt proves both records. Neither pool value alone establishes whole-device RAM admission.

## API/worker gap and bounded integration

`api.py:_verify_result` (`139-227`) already binds artifact bytes/hash, request hash, selected module order, ordered project identity/startup, prepared-content receipt, SAVE-service disarmed flags, codec hashes, and false admission/hardware/playback fields. It does not inspect `compressed_wave_tables`, `flash_plaits_wavetables`, `instance_pool_bytes`, indexed mode, table raw/packed hashes, or catalogue freshness metadata. The worker image's nested verification file is hash-bound by the builder, but the service currently treats that digest as opaque. Thus the app builder has meaningful table checks, but the service response does not independently enforce that the worker built the requested table policy or matching module-derived table set.

Smallest safe extension, still diagnostic-only:

1. Add a strict, named policy field to `BuildRequest` (a `Literal`/enum with only reviewed server-supported layouts); never accept arbitrary compiler flags, table namespace lists, byte budgets, paths, or an `installable` override. Keep the currently used `flash-plaits + compressed-required-banks` policy as the compatibility default until a separately reviewed profile is chosen. The alternative full-compressed policy should be explicit and only meaningful when selected modules include Macro/Shapes consumers.
2. Carry the admitted policy through canonical request hashing and the fixed worker request. `build_demo_image` maps that enum to fixed CLI options and retains the existing module-derived namespace calculation and source pins; browser JSON must not directly determine a namespace list. Unknown profile values should be rejected before queuing.
3. Before returning success, service validation should compare the image receipt's named profile (new explicit receipt field), indexed-TFT/voice settings, exact expected namespace set derived from admitted modules, table raw lengths and hashes, and residual pool formula with independently pinned expected policy/source data. Reject absent, extra, duplicate, stale, mismatched, or malformed table records and verify the expected pool exactly. Keep every existing `installable`, storage-admission, hardware, playback, and full-song-acceptance flag false.
4. Keep the current adapter's immutable source commit and image digest; its checked-out source commit and catalogue must continue to be exact and clean. Do not reuse a catalogue across changed sources unless the existing full `source_manifest` check passes, and retain its all-55-module, indexed TFT, 12-voice constraints. `prepare_wavetables` also sources assets from pinned repository files and pins `tinf`; preserve these upstream/source hashes in the verified link receipt.
5. Add focused tests at both edges: API rejects extra/unknown profile values; worker receives only the server-mapped options; positive end-to-end receipt matches module-derived table namespace set and exact pool; tampering a namespace, table size/hash, mode, or pool is rejected; missing/stale table metadata is rejected. Existing unit coverage (`tests/test_native_module_selection.py`) tests the namespace mapping and `tests/test_native_instance_pool.py` exercises 165,376/196,608/216,064 host pool sizes, but `tests/test_installer_service.py` has no wavetable receipt validation as of this base.

The API should continue to return `installable: false`. This work would make compressed-table selection and diagnostic receipt correspondence explicit; it would not establish device storage capacity, flash writes, package admission, or physical/runtime playback acceptance.
