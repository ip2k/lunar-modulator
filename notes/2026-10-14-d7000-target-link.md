# Fresh Event Horizon target link under the D7000 budget

## Result

A fresh pi32v2 link of the all-production-modules Event Horizon Showcase configuration passed the `expanded-d7000` link budget. The flattened app is **845,036 bytes** (SHA-256 `5709ac03377a310eefdff563f4f08fe8a0e932ed9e0ecacef96464a59ec48573`). The D7000 layout allows **860,644 bytes**, leaving **15,608 bytes**. This is a target-toolchain link and static-audit result, not an installable candidate or evidence that a rescue stage is safe to use.

## Limits and next gate

`expanded-d7000` is a link-time reservation profile. This experiment does **not** prove physical flash ownership or protection, SPL behavior, validity of a rescue record/loader, power-loss rollback, loader transport, raw-candidate construction, package admission, installation, boot, audio/perceptual acceptance, or full-song runtime. In particular, arithmetic slack below `0xD7000` does not authorize writing the proposed `[0xD7000,0xD9000)` stage. The exact installed image and recovery path still require the coordinator's separate admission and watched-hardware gates. No device, USB, MIDI, flash, power or reboot operation was performed.

Semantic-tool coverage was limited: Rarefaction and Serena sessions selected the Mac checkout rather than this isolated Hera worktree, and I did not retarget shared MCP state while other workers may be active. The measurements above come from the exact pi32v2 build receipt, hashes, map and source checkout on Hera.
