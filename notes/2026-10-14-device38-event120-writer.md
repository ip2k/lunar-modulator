# Device38 Event120 injected writer policy

This checkpoint adds a device38-only transaction policy and a one-use adapter. It admits only the exact fresh device38 dual-read receipt and separately pinned candidate/stock transactions. Tests inject transport and do not open an SG device; no hardware readiness is asserted.

The policy binds native install/restore to the exact 208-sector Event Horizon plan and stock install/restore to the exact 213-sector restoration plan. Each commits sector 0x4000 last. Restore semantics write the c543 baseline. Native candidate admission binds the candidate raw receipt, image receipt and transport-manifest raw hashes, plus the transport manifest's canonical JSON hashes for the candidate and image objects. It verifies the image's 845,036-byte app hash, Event Horizon startup index/project, 120-second song-diagnostic setting, full-song acceptance false, and project-save storage/flash/runtime/hardware flags false. The stock transaction binds its pinned stock target. Both variants bind the fresh USB 1-1 / bus1 device38 / 4c4a:8057 observation and matching complete reads.

The adapter accepts only a bounded campaign with an observation no older than 120 seconds. It verifies source and evidence digests, exact variant and plan hash/count, SG/sysfs mapping, private output-parent permissions, and a per-direction/variant consumed marker before opening an SG device. It fsyncs the one-use marker and intent/event transcript before the session may issue a command. No upload, reset or retry path is provided. Event names remain compatible with the coordinator verifier: native_transaction_prepared, durable_intent, operation_returned, sector_verified, native_transaction_completed (or native_transaction_stopped).

Focused tests use a fake session and passive mapping; the mock refuses any construction of RehearsalSG. The 9/9 passing tests cover both plan directions, canonical receipt correspondence, one-use mock success, stale observation, changed binding/plan/direction, and a failed session that latches the no-retry marker. These tests validate policy and orchestration only. They do not validate SG_IO, loader behavior, NOR writes, rollback after power loss, USB exclusivity or boot. The transport manifest still records settings migration and recovery as unverified, and all hardware/installability flags remain false.

The adapter reuses RehearsalSG and BoundDiagnosticSession interfaces: prepared.check, campaign hash, mapping, bridge, header type, policy direction/order/target/baseline and device binding. The coordinator must review the exact campaign/output shape and independently replay the complete transcript before any later physical use. This checkpoint authorizes no physical operation.
