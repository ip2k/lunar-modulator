# First-format recovery campaign model

Date: 2026-10-14. Follow-up branch codex/2026-10-14-first-format-recovery-corrections, based on exact coordinator commit dfc4894c81c846b5ba3ebf27653212b6c6f12157 plus the prior offline model commit.

[verified] The pure offline planner still binds two matching 1 MiB snapshots, their explicit SHA-256, caller-asserted target identity, two private archive references, the fixed 24-sector map, protected complement extents, the 43,130-byte payload bound, and false hardware/admission flags. It now records a SHA-256 and explicit all-FF boolean for each mapped 256-byte trailer page without requiring the page to be pre-erased. This permits the model to describe the archived dirty baseline while retaining the snapshot as rollback source.

[verified] The journal now supports a ROM-held, range-specific recovery sequence for an interrupted first erase. An exact unchanged-sector readback permits retry; exact erased-sector readback advances; a mixed readback retains the active sector identity and enters inspect-only state. A restore_started observation must bind that sector, the latest complete readback digest, an exact baseline sector digest, and one of the plan's archive references. Restoration requires a complete 4 KiB readback. A partial or uncertain restoration remains stopped and can be inspected/retried; only exact baseline readback clears the active sector and allows reverse rollback of already-erased sectors. This is a journal of supplied operator observations, not proof that ROM mode, archive bytes, or flash behavior are real.

[verified] Journal validation now replays every event through transition validation after checking sequence/hash links. Recomputed hashes cannot legitimize an out-of-order sector event; a regression test forges a correctly rehashed but semantically impossible journal and verifies rejection. Physical/admission claims stay false and no command or device-I/O surface is emitted.
