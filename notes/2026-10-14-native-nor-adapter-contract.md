## Minimal integration

Leave the transaction/journal in `firmware/native/project_store.h` and `project_save.h`. Add a single opt-in platform binding such as `firmware/native/project_nor_adapter.c` that owns a const immutable `lunar_project_storage_profile`, observed JEDEC ID and transport context, then binds the four `lunar_project_io` callbacks. Do not widen the shared `FL_RANGE_OK`: Dinghy's `src/platform.c:69-72` narrows it to OTA and its own `0xfc000` settings sector. The profile header says it only validates geometry and assigns no ownership (`project_storage_profile.h:3-5)); no production profile instance exists.

Before exposing callbacks, read JEDEC with a status-returning operation; require observed and declared values exactly `0x856014`, then validate the full immutable profile. Require `layout_verified == 1`, 1 MiB/4 KiB/256-byte geometry, bounded nonempty allowed extents and no protected overlap. Only an independently sourced and approved partition map can provide the extents and set `storage_admitted` to exactly 1. Geometry constants or retained backups alone do not establish ownership.

Callback behavior:

| I/O callback | Binding contract |
| --- | --- |
| `read(ctx, off, dst, n)` | Reject null, zero, overflow, out-of-device and non-owned ranges; split to bounded chunks and return success only after all bytes arrive. Current `fl_read_ram` has no address check (`fm1_flash.h:202-210`). |
| `erase(ctx, off)` | Exactly one aligned 4096-byte sector; validate with `lunar_project_storage_erase_allowed(profile, jedec, off, 4096)`; complete one bounded erase, then independently verify the sector reads erased. |
| `program(ctx, off, src, n)` | 1..256 bytes, inside one physical page and one allowed extent; validate with `lunar_project_storage_program_allowed`; return failure on any transport/WEL/WIP error; read back and compare before success. `lunar_project_write` already splits on page boundaries (`project_store.h:87-99`). |
| `validate(ctx, off, n)` | Stream the whole serialized project through the existing format validator, without applying records to live state. Preserve malformed-file vs transport-uncertainty result semantics (`project_store.h:20-23`). |

This fits the existing transaction: `lunar_project_scan` checks header, payload hash and format (`project_store.h:47-71`); `lunar_project_begin` targets the inactive slot and erases by sector callbacks (`:73-84`); `lunar_project_commit` verifies the payload, writes/readbacks the header and programs the commit word last (`:101-116`). Preserve service generation consumption/no implicit retry (`project_save_service.h:22-27`). Any callback error must fail SAVE and must not be reinterpreted as an empty slot or successful commit.

## Transport gaps that block enabling it

* **IRQ state:** `fm1_flash.h:228-229` saves no state: `irq_save()` executes `cli` and returns zero; `irq_restore()` unconditionally executes `csync; sti`. This is not exact restoration. The current main-loop quiesce path expects entry with IRQs enabled (`save_quiesce.h:5-8`) and calls off/on (`:15-28,31-38`), but that narrow invariant does not repair the generic HAL wrapper.
* **Compiler evidence:** With the pinned 2025-03-24 pi32v2 compiler and `-target pi32v2 -mcpu=r3 -mfprev1 -ffreestanding -O2 -S`, an offline syntax probe for read-PSR / `cli` / write-PSR compiled to `r0 = psr; cli; psr = r0; rts`. Repo code reads PSR in `crt0.S:12-17`; `fm1_isr.S:10-16` saves/restores it only in exception entry/return. The probe proves compiler parser acceptance, not semantics or safe ordinary-C use of a full PSR write. Verify the AC79/pi32 ISA semantics and generated code before adopting it; otherwise use a tiny reviewed assembly guard with a verified interrupt mask. Do not retain unconditional `sti`.
* **XIP-off state:** `fl_enter` disables SFC and remaps pins (`fm1_flash.h:96-112`); low-level helpers are always-inline and RAM entrypoints use `.ram_text` (`:16,144-210`). Linker scripts reserve RAM text at `0x01c00000..0x01c06000` (`dinghy/app.ld:14,22-23`; `native/app.ld:16,32-33,47`). The complete command, error, cleanup, timeout and restore callgraph plus buffers/state/output pointers must remain in RAM until XIP is restored. Also, `fl_exit` restores SPI and SFC but forces IOMAP bit 5 on (`:114-121`); capture and restore its previous value or prove the entry invariant. Every exit must deassert CS and restore each changed peripheral.
* **SPI error propagation:** `fl_spi_wait` is bounded, but `fl_tx`/`fl_rx` discard its result (`fm1_flash.h:68-90`). Thus command, status and read bytes are trusted after timeout. Make TX return status and RX use status plus an output parameter, then propagate through address, WREN, WEL/status, JEDEC, read, erase and program. Check WEL only after a successful status read. Current zero/all-ones JEDEC/status sentinel results also conflate errors and values (`:146-164`).
* **Watchdog:** startup arms WDT with `0x0D` (`src/platform.c:305-314`); `fm1_wdt_feed` is a P33 transaction and its header says call with interrupts off (`hal/fm1_sys.h:3-8,32-76,85-93`). Dinghy erase can keep XIP and global IRQs off during WIP polling for up to 500 ms; program up to 10 ms (`fm1_flash.h:166-199`). The timer comment maps `0x0A` to 1 s and `0x0F` to 32 s, but exact `0x0D` timing, remaining watchdog interval and target NOR latency are not proven here. Feeding before/after each callback while XIP is available is necessary, but does not solve a timeout inside one indivisible erase. Prove deadline margin or add a separately audited RAM-safe feed path.
* **Unrelated interrupts:** service contract requires I/O to safely permit unrelated interrupts (`project_save_service.h:22-27`). Current erase masks them for the full WIP poll. ISR wrappers/callees are not demonstrated RAM-resident while SFC is off, and source does not establish same-chip read-while-write safety. Do not simply enable IRQs during SFC-off. Resolve with primary SoC/NOR evidence and a reviewed RAM-resident ISR strategy, or prove a safe bounded blackout and explicitly adjust the service contract. Until then, direct reuse is incompatible with the service promise.

One sector/page per callback lets the main-loop service schedule and feed between units, but does not alone solve the current long IRQ-off erase. If WDT support is added within SFC-off code, the feed and all P33 helpers must themselves be audited in RAM and obey the IRQ contract.

## Implementation verification gates

1. Host tests: profile overflow/bounds, wrong JEDEC, unverified layout, protected/foreign ranges, misalignment, zero/oversized/cross-page program, injected SPI/WEL/WIP/timeout/readback errors, and proof that failure is not retried or surfaced as success.
2. Compile with the exact `tools/native/Makefile` pi32v2 flags; inspect map and disassembly for all RAM entrypoints and transitive callees. Reject XIP code/constants, non-RAM buffers/state, compiler helper calls, unbounded loops and overlap with `0x01c06000`. The prior retained SAVE ELF has four-byte `r0=-1; rts` erase/program stubs; source presence is not an enabled writer.
3. Keep normal/default images non-writing. The adapter should be opt-in and admission false absent a separately reviewed physical profile; map/package/receipt must preserve false gates until independently approved.
4. Recheck backups, sector ownership, migration and power-cut behavior against actual retained baseline and authorized device plan before physical SAVE acceptance. Simulation cannot establish physical protection bits, NOR timings or power-loss behavior.
