# Installer source-dependency preflight

The private installer chooser now catches omitted modules before exporting a build request. For every selected project, the generated catalogue carries an informational dependency scan derived from the exact project JSON. The exporter reads sounds[].engine, sounds[].inserts[].engine, sounds[].midi_fx[].engine, master[].engine, and mod.rack[].kind, then checks the discovered identifiers against the canonical engines, effects, midi, and modulation catalogue groups. Nullable insert and MIDI-FX entries are accepted as empty slots. The project source is already content-hashed by the catalogue exporter; dependency metadata is shipped alongside that source entry.

The browser checks only selected projects against the user-selected module profile. If a selected project needs an unchecked engine/effect, the chooser presents the project and missing IDs and refuses to export until the user enables them or removes the project. It does not silently mutate module choices, and unrelated unselected project dependencies do not constrain the request. Source paths, content hashes, and dependency claims remain outside the user request payload. Missing, malformed, duplicated, or non-canonical dependency metadata fails closed in the chooser.

This is a user-facing early warning, not an admission result. The existing backend prepare_selection packed-record dependency validator remains authoritative; its validation status remains pending and does not consume the new browser field. All release/admission/default flags remain false or pending. The Event Horizon Showcase remains a reversible proposed full-song chooser default; this work does not establish owner musical acceptance, image installability, or native device playback.
