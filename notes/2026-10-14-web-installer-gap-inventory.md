## Goal and current status

The product goal is a web-based build/install path for Lunar on the FM-1: all 13 production engines available, Event Horizon as the approved default song, selectable engines/effects/projects/sets, an SDK-free native app, and use of `fm1.designburgapps.com` if that is an owner-controlled service origin. The implementation has substantial request, selection, build, verification, and offline packaging pieces, but no installable/downloadable browser result and no admitted transport to the device.

## Dependency-ordered implementation path

1. **Bind a supported build tuple.** Keep the browser's module/profile, project IDs, optional SET IDs, startup index, and parent relation as one canonical request. Reuse `prepare_demo_selection.py` and `build_demo_image.py`; keep API `_verify_result()` as the independent exact-request/receipt check. Each tuple must produce the existing app/ELF/image receipt and exact target link/resource audits. Add a test covering a representative selectable tuple, invalid parent/startup, and a target-link refusal; retain the 13-engine catalogue and Event Horizon default.

2. **Generalize composition behind a separate trusted packager.** Reuse the strict nested-format logic in `model_092_app_replacement.py` and the composition/verification flow in `compose_500_d7000_candidate.py` rather than widening the ordinary builder's mounts. Make the packager consume an immutable completed build tuple (app, ELF, source/toolchain/catalogue digests and request) plus a separately provisioned trusted reference. Emit a package only for a named target profile with explicit input hashes, identity, layout, protected decoded component hashes, and independent parse/CRC verification. Keep references and private device backups on the owner-controlled packaging boundary; never accept a caller-supplied `installable` bit. Test exact baseline round-trip, changed bytes at protected ranges, wrong app/ELF receipt, over-bound length, CRC corruption, and wrong target identity.

3. **Select the actual install transport.** The preserved-stock FWSC route and expanded D7000 raw-flash route have different formats and recovery assumptions. Reuse the strict 092 package model and exact FM-1_500 offline composers only as test references; they are not general admission. Stock package guarding still requires byte-identical SPL/OTA/config/CFG, while expanded raw candidates require their separately audited recovery/layout procedure. Before implementing a writer, establish which transport the target hardware/updater accepts for the exact app and keep the other profile unavailable. Do not infer stock updater acceptance from a valid FWSC parser or from raw-image geometry.

4. **Add owner-scoped package retrieval.** After package verification is complete, bind package bytes and receipt to the exact build ID and requester. Add authenticated/authorized artifact retrieval and explicit deletion/expiry with bounded file size and `Cache-Control: no-store`; define origin/CSRF policy and durable job cleanup across server restart. Add API tests for cross-owner reads, expired/deleted artifacts, byte/hash mismatch, and non-installable diagnostic-only results. The current in-memory status admission map and opaque IDs do not meet that boundary.

5. **Wire browser admission only to the independent verifier.** Extend the package verifier/OTA adapter so it validates the actual emitted container and nested records, target identity, protected-component equivalence, and transport limits before returning `logicalImage`. Add tests for forged headers, nested size/CRC failures, wrong firmware identity, modified protected data, and package/app receipt mismatch. Keep a visible diagnostic-only state until all those checks pass; the UI must not display installable merely because the API finished or a file downloaded.

6. **Integrate only with a verified service origin and later acceptance gates.** Confirm control of `fm1.designburgapps.com` and its deployment/auth/routing before changing the static page's same-origin opt-in marker or pointing it there. Then separately prove the exact downloaded package through its target transport, recovery procedure, device boot, 13-engine availability, Event Horizon playback, and SAVE/reload. Static Pages publication, local browser E2E, target link, package parsing, device install, and perceptual acceptance are separate results.
