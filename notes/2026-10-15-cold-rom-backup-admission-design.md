# Cold-ROM paired backup admission after USB_KEY entry

## Status and scope

This is an offline design review on branch `chore/2026-10-15@cold-rom-admission`, based exactly on `4ab06ff15fe99865b4ec379c562b465fc28e5eec`. It proposes a separate read-only admission path for the case where the owner has just entered mask ROM using the Cynthion USB_KEY route. It does not assert that USB_KEY has succeeded, that ROM or SG is currently present, or that the physical dongle wiring is qualified. No USB, SG, MIDI, Cynthion, flash, reset, or power operation was performed. No existing source, loader bytes, or allowlist was modified.

The existing `tools/fm1_fixed_loader_backup.py` is not a valid entry-proof consumer for this case. Its `validate_entry()` requires an ordered normal-mode identity query decoding to `FM-1_092`, the exact soft-key SysEx `F0 22 24 35 7D F7`, then ROM enumeration at that same topology. Fabricating those events after USB_KEY would falsely claim a soft-key path and FM-1_092 identity. Its manifest also hard-codes `unit_identity: FM-1_092`. Preserve that tool's current contract; add a distinct cold-entry contract.

## What the current read path already bounds

The current fixed campaign pins the 24,064-byte RAM loader (`LOADER_SHA`), loader profile and source, the backup reader, and the adapter source. Its immutable inventory is 8,757 operations: ROM INQUIRY, 47 exact 512-byte RAM uploads at `0x01c02000`, one fixed jump, loader buffer and JEDEC checks, then two ascending full 1 MiB reads in 256-byte chunks with fixed online checks. The only CDB opcodes are `0x12`, `0xfb06`, `0xfb08`, `0xfc14`, `0xfc0a`, and `0xfd05`. The request builder rejects other opcodes, payload/range deviations, and all flash write/erase paths. The SG adapter validates `WL82`/`UBOOT1.00`, flash type 3/JEDEC `0x856014`, direct character-device identity, exact sysfs USB-to-SG ancestry, and the opened descriptor mapping around each call. The existing tests mock SG syscalls and topology.

Keep those exact loader bytes and command inventory. The cold path should have a separate input kind and validator, for example `fm1-cold-rom-entry-v1`, which admits the same reviewed fixed operation inventory only after its own entry evidence validates. Do not make the soft-key validator accept a second branch, loosen its identity check, rewrite old event logs, or change the current loader allowlist. Reuse the fixed reader request builder only through a new pinned adapter that has its own source hash and schema, or factor shared inventory/transport code in a separately reviewed change while keeping both validators strict.

## Cold-entry evidence contract

Before any SG open, campaign construction should validate a bounded, immutable evidence bundle:

1. A private Cynthion/Pico console capture identifies the exact dongle firmware build and records the completed key attempt (`DONE: bus -> PC` or the reviewed equivalent). A timeout, `FAILED`, `FAULT`, missing completion, unknown firmware, or ambiguous console sequence refuses admission. A firmware banner or LED alone does not establish that the FM-1 enumerated.
2. A separate host-side passive USB observation records the pre-attempt state and the new, unique `4c4a:8057` ROM device after completion, plus wall-clock and monotonic timestamps. It must bind the selected physical target/topology explicitly to the owner-operated USB_KEY attempt. The Cynthion log and ROM observation are correlated by a one-use campaign nonce written into the capture directory before the attempt, or by an equivalent owner-reviewed contemporaneous record; do not infer a relation from timestamps alone.
3. The owner attests which physical FM-1 was connected and powered for this attempt and that the observed ROM device is that unit. ROM enumeration exposes no usable device serial in this adapter's current schema; record `usb_serial: null` and `identity_basis: owner_attested_physical_selection`. Do not claim cryptographic or firmware-version identity and do not copy the historical `FM-1_092` identity into this receipt. If the owner cannot confidently correlate the physical unit, refuse.
4. Record fresh USB `path`, `busnum`, `devnum`, VID/PID and product/interface facts from sysfs, requiring exact ROM VID/PID and a single candidate on the selected path. Resolve exactly one SG node through that USB sysfs ancestry; save node/class/device identities and confirm `/dev/sgN` is a direct character device. Do not accept an SG number, pathname, or bus alone as device identity.
5. Pin hashes for the new validator/adapter, current fixed backup adapter and unchanged loader reader, loader blob/profile/source, Cynthion firmware and capture, campaign configuration, and evidence files. Save source paths and hashes in the receipt. Re-open and hash every required file before admission; reject symlinks, non-regular files, schema extras, missing fields and reused output directories.
6. Consume the entry evidence once by durably creating/fsyncing a one-use marker in the unique private campaign directory before the first SG open. Any command intent without a proven completion, open/ioctl error, disconnect, binding change, storage error or process interruption is ambiguous and permanently consumes that admission. No retry under a new output name may reuse the same evidence hash.

Freshness should be checked at the actual admission/open boundary (proposed maximum: 120 seconds from the recorded completed ROM enumeration), not repeatedly against the entry timestamp during a valid paired dump. Start a separate monotonic whole-session deadline after open (proposed hard cap: 600 seconds) and retain the 3-second per-ioctl timeout. Check current sysfs and descriptor identity before and after every SG command. The numerical aggregate cap needs offline test coverage and should be adjusted only through a separately reviewed source change; this review has no device timing measurements.

## Receipt and acceptance semantics

Write the two dumps to exclusive mode-0600 files in a mode-0700 unique directory; fsync each dump and directory before computing the final accepted receipt. Require every planned operation and completion in order, exactly 1,048,576 bytes per dump, independently rehash both durable files, and require byte-for-byte equality. The receipt should identify `capture_kind: paired-current-flash-read`, `flash_image_classification: unclassified`, `current_flash_sha256` (only after both files are durable and equal), `backup_pair_identical: true`, and `write_admission: false`. It should preserve `physical_recovery_verified: false` and `kernel_exclusivity: false` unless those properties are separately demonstrated.

Equality proves repeatable reads within this session, not correctness of the image, a known prior baseline, recoverability, unit serial identity, or permission to erase/program. Do not compare away, classify, or silently adopt any old baseline in the acquisition tool. The resulting bytes remain an unknown current image for owner/reviewer analysis. A later write proposal would need a separate admission built from these accepted read receipts plus original paired backups, sealed target/plan, exact interrupted write prefix, immutable-range comparison and transaction-specific review. This backup receipt alone must never call a transaction writer.

The transport's RAM upload/jump is permitted only because the exact audited ROM loader inventory requires it; it is volatile RAM activity, not a flash write. The cold campaign must not include any erase, program, reset, boot, eFuse, online configuration, arbitrary opcode/address, shell subprocess or automatic retry path. The existing reader documents that host storage drivers may issue incidental SCSI traffic, so the future receipt must continue to report `kernel_exclusivity: false` rather than claiming a globally exclusive device command stream.

## Required offline tests before any future live acquisition

- Accept a synthetic cold USB_KEY record only when the exact reviewed Cynthion build/result, owner unit-correlation statement, fresh unique ROM appearance, current USB/SG mapping and immutable source pins all match; preparation must perform no open.
- Reject the existing normal-softkey log, a fabricated `FM-1_092` identity, a `DONE` record without ROM enumeration, ROM enumeration without `DONE`, stale/non-monotonic timestamps, duplicate/ambiguous ROM candidates, wrong path/VID/PID, missing owner attestation, changed serial/topology fields, reused nonce/evidence, and each changed source pin before SG open.
- Verify the fixed 8,757-command inventory is byte-for-byte the pinned reviewed inventory and every address is exact; negative tests reject every write/erase, reset, arbitrary RAM, unknown and post-completion command. The old fixed-loader adapter tests remain unchanged and passing.
- Simulate correct two-pass full reads and verify durable file lengths, SHA-256, equality and unclassified/no-write receipt flags. Reject short/extra data, mismatched dumps, bad FC0A/JEDEC, bad buffer size, SG sense/status/residual errors, interrupted intent/completion pairs, close/reopen, changed fd/sysfs mapping, output collision, symlink, marker collision and fsync failure. Every rejection after admission consumes the one-use marker and does not retry.
- Test admission freshness immediately before SG open separately from the monotonic whole-session deadline; crossing 120 seconds before opening refuses, while a valid session may continue past the entry's 120-second age and stops before a later call once the independent 600-second session cap expires.

These are proposed tests, not tests implemented or run by this design task. The existing focused adapter tests are also not green in the default Xcode Python because `pytest` is not installed there; rerun them in the project/approved Hera environment before depending on them.
