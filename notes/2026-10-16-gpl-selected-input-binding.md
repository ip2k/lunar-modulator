# GPL source bundle: selected project and SET source bytes

**Insight — before:** the prepared-profile manifest digest was already in the trusted build tuple, and `load_prepared_profile` checked `content-NN.source` hashes. The GPL bundle generator had no prepared-profile argument, however, and could only archive extension-selected committed source files. It explicitly left project/SET source inputs unresolved.

**Insight — after:** `PreparedInputs` now exposes the exact source bytes it has just read and verified. The bundle can optionally accept the tuple-bound prepared directory, validate its request and selection receipt, and place only those selected original project/SET bytes into deterministic archive paths. No source file is reopened between validation and packaging.

`tools/native/create_gpl_source_bundle.py::build_bundle(..., prepared_dir=None)` preserves the old invocation when no prepared snapshot is supplied. With a snapshot, it requires tuple `prepared_profile_sha256` and `request_sha256`, validates the prepared profile through `load_prepared_profile`, then checks the adjacent `request.json` and `selection.json`: the request digest is the tuple digest; selection status and prepared-manifest digest match; project ordering, startup project and SET parent match the request; receipt content rows agree with prepared asset source identities and digests. Only the validator-returned `source_content` bytes are added, at `selected-inputs/projects/<id>.lunar` and `selected-inputs/sets/<id>.movy1`. Each is recorded with path, kind, ID, optional parent, SHA-256 and byte length in `MANIFEST.json`.

When inputs are bound, the manifest no longer lists project/SET source bytes as unresolved, but it continues to state `corresponding_source_complete=false` and `distribution_eligible=false`; the external JieLi toolchain remains unresolved. With no optional snapshot, the prior explicitly incomplete behavior remains. Tuple and selection admission flags are still required to remain false.

Validation: `uv run --offline --with pytest pytest -q tests/test_gpl_source_bundle.py` passed (12 tests), covering deterministic output, exact archived bytes and manifest metadata, tuple/prepared digest mismatch, modified source bytes, omitted/extra content, symlinked source, escaped path metadata, selection identity mismatch and fail-closed admission flags. `python3 -m py_compile tools/native/create_gpl_source_bundle.py tools/native/verify_image_profile.py` passed. The broader content-embedding/image-profile suites were attempted but require `FM1_STATE_TOOL`; that external state-codec dependency was not supplied, so those suites did not run successfully. No firmware build, hardware test, release, or installability claim is made.
