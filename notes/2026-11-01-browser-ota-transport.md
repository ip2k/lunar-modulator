## Offline contract

The only controller entry point is `installFromUserAction`. With an audited verifier and explicit access/selector injected, it enforces package verification before MIDI access, exact `FM-1_015` running identity, a separately selected matching port pair, the `7F` upgrade command, a 2000 ms stock pause, E0000000 verification finish with ACK, a 3000 ms verify-ACK port hold, re-enumeration, exact `ota-FM-1_015` loader identity, the second `7F` command, F0000000 write finish with ACK, and a fresh `FM-1_NNN` identity equal to the admitted package. The adapter pins a snapshot of the package and logical image by SHA-256, and keeps its admission/session/resume objects private to its instance. Neither a flag such as `admissible: true` nor a fabricated handle can make the public verifier accept a package. The controller exposes no write-stage cancel control. An unexpected finish address or length is rejected without an ACK.

The final return value says `application-identity-confirmed`, which is an identity observation, **not** audio, control, watched boot, or physical recovery acceptance. A `success\0` finish ACK alone never reports success. [reported] `docs/03-update-protocol.md` describes the stock 2000 ms pause, 3000 ms verify-ACK hold, 8-byte finish requests and about 6 s mode changes. The browser still has no admissible firmware package and no public install path. The owner's current physical FM-1 SysEx policy permits only the identity query, so these synthetic tests issued no USB/MIDI/device traffic.

## Remaining release gates

A separate audited verifier must prove the exact package, protected stock head, unchanged OTA/cfg/layout and target identity before injecting `packageAdmission`. The request/build service currently returns summaries and explicitly non-installable candidates. Its artifact SHA and service receipt are not admission. After a real package exists, integrate the controller into the installer with a reviewed visual/user flow and offline browser tests. Any OTA transfer on the owner's FM-1 requires a separately authorized install session and staged hardware recovery/boot acceptance; this code and the tests do not authorize one.
