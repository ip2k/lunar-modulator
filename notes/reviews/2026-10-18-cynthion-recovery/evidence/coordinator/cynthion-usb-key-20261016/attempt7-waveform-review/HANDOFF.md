# Attempt 7 key/SOF waveform review

Date: 2026-10-16 (read-only review)

## Finding

Attempt 7 completed a bounded key attempt and entered `WAIT_DP`, but it never observed the expected D+ J state and never entered SOF. The terminal register result is WAIT_DP timeout after 500,000 us; packet count 832; SOF count 0. The timeout-triggered USB3343 Debug register 0x15 read completed without error and returned SE0. The cached RXCMD value was also valid SE0 and 500,260.05 us old; terminal GPIO was 0 (both pad OEs off). This makes a stale cached J hidden from the timeout path unlikely. It does not tell whether the FM-1 was unpowered, whether its ROM held the bus down, or whether a ROM ACK actually occurred and failed to transition to its pull-up state.

The event ring supports two competing interpretations, so it does not justify calling the ACK genuine or false. During the released GAP, the PHY changes from the driven line state to SE0; at the next KEY start the cached state is still SE0. In later key bits, RXCMD changes between SE0 and K, and the candidate counter ultimately reaches 100 us. This is consistent with a genuine ROM clamp beginning during keying, but does not establish it: the fixed 1 kOhm GPIO path, target-side bias/power, and PHY line-state observation leave the origin of the held SE0 ambiguous. In either interpretation, the required post-ACK D+ J/pull-up was absent for the full 500 ms wait.

The read-only captured evidence is `scratch/cynthion-usb-key-20261016/debug-readback-control-power/owner-attempt-7-status.json` in the integration worktree. Register 0x60 is `3` (snapshot valid + attempted, no read error); 0x61 is `0` (raw Debug 0x15); 0x62 is `1` (valid cached SE0); 0x63 is `30015603` 60-MHz cycles (500260.05 us); 0x64 is `0` (terminal GPIO/OE snapshot). Protocol receipt 0x0c is `2133` (WAIT_DP timeout); 0x0d is 832 packets; 0x0f is 500000 us; 0x10 is 0 SOF us. The datasheet defines Debug 0x15 Linestate bits as the current DP/DM line state; see the [USB334x datasheet](https://ww1.microchip.com/downloads/aemDocuments/documents/UNG/ProductDocuments/DataSheets/USB334x-Data-Sheet-DS00002646A.pdf), section 7.1.3.5. That read is an observation of the PHY-side state, not direct voltage evidence at the FM-1 connector.

## Comparison with the reported Pico implementation

The local project's source review of czietz's unlicensed gist records: SPI1 at 50 kHz, D+ as SCK, D- as MOSI, mode 0/MSB-first, a two-byte `16 EF` transfer per newly created/released SPI instance, 3,000 packets, then a 1-kHz 50%-duty D+ PWM for 2 seconds, repeated forever. It performs no ACK or pull-up detection. The original gist is linked from [docs/10-usb-key-dongle.md](https://gist.github.com/czietz/9a94cf3c3e68f2ceb45fab682e1cbbd5); its code has no licence, so this review summarizes it rather than copying it.

The Cynthion profile shares the nominal 50-kHz D+ clock and MSB-first key, but its bit waveform is deliberately 8 us low + 12 us high (40/60 duty) rather than the Pico SPI peripheral's nominal 10/10 us clock. Its 16-bit packet takes 320 us; its 160-us released gap makes a 480-us packet cadence, and the finite 30,000-packet bound is 14.4 seconds. Thus matching the clock rate alone does not reproduce the Pico's packet cadence or 50% clock duty. The Pico sends roughly 0.96 seconds of clock bits per 3,000-packet burst, plus interpreter/setup overhead, then spends 2 seconds on PWM. It neither proves that ACK sensing works nor says whether its own PWM, a later PC connection, or another power-up detail supplied the ROM's calibration edges. The anecdotal FM-1 success is useful precedent for the broad sequence, not a validated waveform/timing recipe for this unit.

The electrical difference is material. The Pico wiring described in the gist has no series resistors; Cynthion GPIO reaches the target through fixed 1-kOhm resistors. Local docs report the FM-1 ROM's approximately 15-kOhm line pulldowns while listening, a 1.5-kOhm D+ pull-up after ACK, and the need for external pull-ups below 4.7 kOhm for dependable ACK sensing. The gateware README calculates that a GPIO SOF low through 1 kOhm against a 1.5-kOhm pull-up would leave about 1.32 V at the target side, above the USB full-speed VIL maximum of 0.8 V (ideal divider; not a measurement). Therefore a Cynthion GPIO PWM is not electrically equivalent to a compliant host's low pulse, even if its edge schedule resembles the Pico PWM. Sources: `docs/10-usb-key-dongle.md` §1.1, `tools/cynthion_usb_key/README.md` lines 93-101, and `tools/cynthion_usb_key/gateware.py` lines 313-321, 407-436, 455-469.

The current core only enters SOF after it sees a valid J state in WAIT_DP; its SOF path has therefore not been exercised in attempt 7. The 500-ms SE0 observation is evidence against a completed ACK-to-pull-up transition, but it cannot distinguish no target power from ROM/protocol failure. Root's clean postconnection safety gate and CONTROL-to-TARGET-A selection do not themselves measure the FM-1's VBUS or battery voltage.

## Recommended discriminator (owner-controlled, not executed)

Do not repeat the same ACK-triggered operation attempt. First use the coordinator's pending passive TARGET-C enumeration result and, if it remains absent, establish target power at the connector with an owner-approved measurement or other independent read-only indication. Without verified target power, another key waveform trial cannot distinguish timing from an unpowered ROM.

If target power is independently established, the useful protocol discriminator is one owner-reviewed, bounded experiment that logs line state throughout a changed key burst and distinguishes (1) a target-side low clamp during active key transmission, (2) post-key D+ pull-up/J, and (3) post-key SE0. A blind key-burst-then-SOF sequence is a plausible hypothesis from the Pico report, but it must not report success merely because its timer expired. Keep the current fixed resistors, terminal high-Z behavior, finite watchdog, and no-publication/no-flash limits. Before attempting SOF, prefer the USB3343's reviewed transmit path (or a maintained, reviewed USB host/PHY implementation) over GPIO PWM: the PHY can create a stronger USB line level without bypassing the GPIO resistors, but changing ULPI transmit mode has not been designed or validated here. Any such change needs isolated/disconnected loopback and power/drive review first.

A result showing a genuine line transition to J after key release, then expected SOF response, would discriminate protocol progress. Persistent SE0 with independently verified target power would point toward key timing/line-level/ROM ACK behavior; persistent SE0 without independent power evidence remains inconclusive. One instrumented trial can test these conditions; more identical retries do not add useful information.

## Limits and ownership

This was a read-only source/log review. No code, bitstream, hardware, power, or USB state was changed. No new host/SOF implementation was built. The event ring only reports PHY decoded state and FPGA-side GPIO; it is not a voltage capture at the target connector. The ROM timing descriptions are reported in the repository from upstream/community sources, and the Pico result is anecdotal; neither was revalidated on this FM-1. Root remains the sole hardware operator and must review any next physical experiment.
