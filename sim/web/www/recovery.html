FM-1 recovery

Bring an FM-1 that no longer boots back to stock V15, or restore your own backup. The browser cannot claim the FM-1's mask-ROM USB interface (WebUSB protects mass storage), so this route goes through a Raspberry Pi Pico 2 W that does the key and the USB host work, and the page talks to the Pico over Web Serial.

Needs Chrome, Edge or another Chromium browser on a secure page (https or localhost). Firefox and Safari have no Web Serial.

This writes the FM-1's flash. Use it for a unit that does not boot, or one you have decided to return to stock. The boot area 0x0-0x4000 is never written, by this page or by the transporter. A write that stops part way leaves the application region half written; the unit can be keyed and rewritten again.

The wiring is push-pull with no series resistors, as upstream designed it. That is an owner-approved exception for the owner's unit only (docs/17); decide it consciously for yours.

Never with a running FM-1 attached. Soft-keying a running stock V15 into the mask ROM is off limits. This page never sends that command and refuses to continue if the transporter reports a running V15.

0 Put the transporter firmware on the Pico

  1. Build the UF2 from source: tools/fm1-transporter/build.sh (pinned upstream commit plus our patch, in a container). It makes fm1_transporter-pico2_w.uf2. This site does not host binaries.
  2. Unplug the Pico, hold its BOOTSEL button, plug it in, release. A drive named RP2350 appears.
  3. Drag the UF2 onto that drive. The Pico reboots by itself.
  4. It now shows up as USB 2e8a:000a "FM-1 Transporter" with two serial ports. The second one is the data port this page uses; the first is a console.

Upstream source: kurogedelic/FM-1-transporter at a7fb5e8 (MIT). The UF2 flashed on the owner's unit on 2026-10-26 had SHA-256 4f5fab3f…b7f482 [verified]; a rebuild may drift because the build image is not pinned. Wiring and details: docs/17.

1 Wire it

Pico GP0 to FM-1 USB-C D+, GP1 to D-, GND to GND. No VBUS: the FM-1 runs from its battery, so charge it first (a write takes about a minute; a dead battery mid-write leaves the app region half written).

2 Connect

Press Connect and choose the transporter's second serial port (the data port). The page sends only ping to check it. Do not pick the first port: it is a debug console that treats typed letters as commands.

3 Loader

Choose wl82loader.bin from kagaimiq's jl-uboot-tool (24,064 bytes, SHA-256 d41da612…ca5376). It is checked here, stays in your browser, and runs only in the FM-1's RAM. It is JieLi's file and is not shipped with this site.

4 Enter boot mode

  1. Press . The transporter reboots and this port closes.
  2. Press within about 10 s and choose the data port again. The loader must be chosen again too.
  3. Only now switch the FM-1 ON. Within a few seconds the status below should show boot mode.

If you are already in key mode (you started the Pico with the FM-1 off), skip the first two steps.

5 Back up

Reads the whole 1 MiB flash twice, compares the two by SHA-256 and saves both files to your disk. Nothing is written. Keep them.

6 Choose what to write

Either your own 1 MiB backup, or the stock V15 package FM-1.fwsc (699,956 bytes, SHA-256 db1642b2…db8a; see docs/02). Any other package is refused. Only sectors in 0x4000-0x92FFF that differ are written; an image that differs in the boot area 0x0-0x3FFF is refused.


    


    

      
7 Write and verify

      
Keep the FM-1 on and the wires still until the final read is done. If anything fails, do not power-cycle: keep this page and its log.
